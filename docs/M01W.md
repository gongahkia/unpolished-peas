# M01W work-cart format

`M01W/2` is the source-visible authoring format for MOD-01 revision 2. A work-cart is
one UTF-8 TOML document with the `.m01w` extension. It is the editable source of truth;
the deterministic `.m01c` cartridge is its packed distribution form.

## Top-level document

The first key is always `format = 2`. Unknown top-level keys are rejected. The document
contains one `[cartridge]` table and zero or more `[[module]]`, `[[asset]]`, `[[recipe]]`,
and `[[test]]` tables.

```toml
format = 2

[cartridge]
language = "MODL/1"
id = "relay-catch"
title = "RELAY CATCH"
author = "@gongahkia"
version = "0.1.0"
entry = "src/main.modl"
update_rate = 60

[[module]]
path = "src/main.modl"
source = '''
on draw:
  clear(25)
'''

[[asset]]
name = "tiles"
kind = "tile_set"
path = "assets/tiles.m01g"
payload = '''{"revision":1,"kind":"tile_set","tiles":[[0,0,0,0,0,0,0,0]],"flags":[0]}'''
```

`module.path` and `asset.path` are normalized relative project paths. `module.source` and
`asset.payload` are retained byte-for-byte in the packed source work-cart. Asset payloads
are UTF-8 JSON matching the declared asset kind. Paths and asset names must be unique.

## Recipes and tests

Recipes are author-time operations. They never run in a cartridge. Both built-in algorithms
require an unsigned `seed`, an output map asset name, and bounded dimensions. `noise` selects
from declared tile IDs; `wfc` derives patterns from a declared source map. Materializing a
recipe replaces only its named output map payload.

Tests stay inside the work-cart as named MODL or replay payloads. They use the existing test
semantics after being materialized into the compiler's internal project representation.

## Packing and compatibility

Packing materializes all required recipes, compiles the internal project, and archives the
exact `.m01w` source as `source/workcart.m01w`. Runtime assets and generated JavaScript are
separate archive entries. Unpacking a revision-2 cartridge restores the exact work-cart.

V2 does not read, write, or import Tiled projects. `mod01 migrate` is the one-time conversion
path for the repository's V1 directory projects. V1 authoring support is removed after all
maintained content has migrated.
