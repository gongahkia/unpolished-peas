# Lantern Leap — full polish review, 2026-11-12

Review mode: **full**. Scope: the complete small game, controls/state transitions,
saves/resource ownership and optional verification. Framework: existing Peas
Canvas/Atlas, nearest pixel sampling and authored Basic font; no second UI system.
Desktop/keyboard/controller authoring example; touch controls are outside scope.
The make-interfaces-feel-better skill’s typography, surfaces, animation, icons and
performance principles are adapted to fixed-resolution Canvas. CSS radii/shadows,
DOM hit targets and SVG-library prescriptions do not apply to this game surface.

## Baseline and design

See [POLISH_PLAN.md](POLISH_PLAN.md) for bounded acceptance criteria and
[GUIDE.md](GUIDE.md) for current commands/controls. Baseline HEAD 76a82556 built
in Debug before edits; real trusted Chromium interaction followed the canonical
Wasm-name correction. Original 160×90 Wasm binaries are retained under root
zig-out/diagnostics/two-games-baseline/original-binaries. The later baseline
recovery serves those unchanged binaries through the corrected filename and
restores their 160×90 canvas. This recovery is labeled in its report; the original
startup failure is retained. Initial build had 10 Neon / 6 Lantern tests.

Pure draw extraction is commit 910a8982: normalized draw bodies and pre-existing
trace/pixel checks established unchanged behavior before intentional polish.
Game goldens change only where the inspected design changed; engine golden
contracts are untouched. Ordinary pilots observe state and issue input; they do
not set positions, health, score, progress or completion.

## Verification and evidence

Ordinary complete route: 680 keyboard ticks / 680 virtual-controller ticks; all six glows, checkpoint, hazard death, immediate checkpoint respawn preserving the collected mask, full restart, completion/replay, best six and audio off.
These are normalized recorded inputs; virtual controllers are not physical
hardware. Trusted browser keys/clicks are tested separately. No external user
playtest is claimed or required.

Current results are retained under root zig-out/diagnostics/. The final result.json
for each command is authoritative; failed exploratory runs remain separate.

- Debug tests: Neon 21/21, Lantern 20/20. ReleaseFast: same full suites pass.
- Normal package/web builds and opt-in export build separately. Static copy fits
  within 304 pixels; tests cover pause, jump/fire edges, save rejection/retry,
  corrupt/legacy records, partial allocation failures and three audio lifecycles.
- Keyboard normalized browser routes: Chromium 157.0.8103.52, Firefox 158.0 and
  real Safari 18.6. Each route compares all nine Neon/eight Lantern milestones,
  actual ending reload and (Lantern) checkpoint reload against CPU references.
  Every RGBA channel must be within 1; independent WebGL/PNG/readback probes and
  explicit shutdown (zero resources/RAF, destroyed phase) pass.
- Chromium additionally passes complete recorded virtual-controller routes.
  Trusted keys/clicks in all three browsers pass start, movement, fire/sprint or
  jump, pause/resume, explicit restart, M preference, rejected-write retry and
  actual reload. Initial audio awaiting_gesture/zero accepted nonzero PCM becomes
  active/nonzero music after a real canvas click, before any gameplay action;
  muting stops new nonzero PCM. No mute-toggle/reload is needed for activation.
- Real native ReleaseFast SDL routes and separate processes reload final saves;
  Lantern additionally runs the prefix through checkpoint/death, then a separate
  process loads exactly that checkpoint/mask. All owned test directories are
  removed after path checks; route-only pacing is excluded from profiling.
- Fresh archive consumers fetch over loopback into a clean cache and build test,
  package, web and the optional exporter outside the checkout (paths with spaces).
  Fetching each game itself verifies manifest retention of tools, guide, review
  and OFL notice. Sources remain unchanged; shipping JS has no replay injection.
  Their retained browser bundles pass the same Chromium/Firefox/Safari routes.
- Core API/public import/docs checks: 48/48 build steps, 40/40 tests; final
  docs/import recheck 43/43 steps, 36/36 tests. Shared
  adapter/replay/save-isolation tests pass independently. Existing READMEs,
  Ashen Causeway, Seed Sprint, unrelated examples and engine files are unchanged.

## Ownership, persistence and profiling scope

See GUIDE for save format and reset rules. The original font/image/OGG and OFL
notices remain; original generated WAV chirps have a retained stdlib generator.
Resources load once across restart. Prepared text borrows immutable font metrics,
so font edits use rebuild; atlas hot reload remains at the native boundary.
Audio unload and failed-init allocation walks cover ownership explicitly.

The optional profile follows the existing Ashen observation pattern, without
modifying Ashen. Its local std-only allocator counter keeps this game portable as
an archive consumer. CPU samples time update/draw/800 stereo audio frames with
real in-memory saves; excludes C/driver/OS allocations and replay/report buffers.
Native samples include ordinary platform storage, audio and GPU presentation;
120 warmup/240 retained frames per 360-frame window, with all raw tails retained.
No capture, report serialization or progress printing occurs in timed callbacks.
Workload windows are early-route and later active-route; they are bounded mixed
play segments, not claims that every frame has identical actors or load.

## Verdict and remaining limits

**Approve** for the bounded desktop example scope: no actionable HIGH/MEDIUM/LOW
interface finding remains from this full review. The five categories were
inspected, including the retained 10% motion sequences. Remaining **unverified**:
physical keyboards/controllers and device feel, subjective listening, external
user playtesting, other hardware/OS/browser versions and long endurance runs.
Touch is out of scope. These limits are not prerequisites for this small-game
acceptance. No engine correctness defect or universal performance claim follows.
Unrelated tail attribution remains deferred rather than expanding this polish.

## Bounded performance evidence

Host: Intel Core i5-8279U 2.40 GHz, Iris Plus 655, Intel macOS 15.7.7;
Zig 0.15.2 ReleaseFast. Actual SDL GPU/Metal host, 960×600 framebuffer and
320×200 Canvas. One full CPU route, then two serial 360-frame native windows;
120 warmup/240 retained frames each. Builds/captures were finished first.
Native profile mode has no route-pacing sleep and no per-frame printing/capture.
The raw 360 samples, including warmup/outliers and zero/catch-up updates, remain
in host-samples.json and host.log. No automatic performance threshold is asserted.

| Native window (actual input ticks) | Frame median / p95 / p99 / max ms | Update median / p99 / max ms |
| --- | --- | --- |
| early-route (0–361) | 16.673 / 17.059 / 17.465 / 33.156 | 0.009 / 0.657 / 0.702 |
| active-route (240–602) | 16.550 / 18.993 / 20.461 / 34.446 | 0.010 / 0.775 / 0.958 |

CPU groups exclude the first 60 ticks and non-playing/dead/completed states. Ordinary = grounded; active = airborne traversal, including the six-glow route
and checkpoint/hazard approaches. Update median ordinary/active is 0.0053/0.0053 ms;
draw 0.357/0.365 ms;
800-frame stereo mix 0.031/0.032 ms.
Ordinary/active retained samples: 248/368.
Counted initialization: 113 growth/allocation events,
1023572 cumulative bytes; live peak 948103 bytes.
Observed ordinary/active loop allocations: 3/13 events,
24/448 bytes (includes in-memory save replacement).
Cleanup returns counted live bytes to **zero**. Replay/report buffers, C allocator,
OS and GPU allocations are outside this counter; it is not a process RSS claim.

The longest retained native frames are 33.156/34.446 ms; their presentation
portions are 32.700/34.069 ms (frames 140/218). Updates remain below 1 ms in these
windows. A single host/session and short route are not endurance or hardware-wide
proof; preserve the tails and investigate separately only if needed.
