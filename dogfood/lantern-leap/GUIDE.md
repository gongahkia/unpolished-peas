# Lantern Leap — current guide

A compact authored platformer: collect six glows and reach the beacon. Current
controls and save rules supersede the historical README. Design/acceptance scope:
[POLISH_PLAN.md](POLISH_PLAN.md). See [REVIEW-2026-11-12.md](REVIEW-2026-11-12.md) for the full visual/playability review and verification evidence.

From this checkout:

```sh
cd dogfood/lantern-leap
zig build run -Doptimize=ReleaseFast
zig build test
zig build test -Doptimize=ReleaseFast
zig build package web
python3 -m http.server --bind 127.0.0.1 --directory zig-out/web 8000
```

Open http://127.0.0.1:8000/?renderer=webgl2 and focus the game. `zig build dev-web`
provides the existing rebuild/reload workflow. Native output is 960×600 logical
window pixels; the game Canvas is 320×200. Package the entire web directory,
including unpolished-peas.wasm and licenses/Basic-OFL.txt.

- Enter / gamepad Start: begin/continue, pause/resume, immediate checkpoint respawn
  while dead, or replay after completion.
- Left/right arrows, A/D, D-pad or left stick: move. Space / South: jump.
- Hold jump for a full arc; release early for a low hop. Coyote allowance and
  landing buffering are bounded to six fixed ticks and consumed once.
- Escape pauses; R / left shoulder explicitly starts a full fresh run.
- M / gamepad Back toggles music/effects and stores the preference.

Death automatically respawns after 30 fixed ticks, preserving collected glows
and checkpoint; Enter requests the same respawn immediately. Full restart clears
current glows/checkpoint while retaining best, completion record and preference.
Pause/death/restart discard jump buffers; a held jump must be released to rearm.
The whole landing range fits ahead of the camera. Collision/hazards/level remain
ordinary fixed-update game code in game.zig/level.zig; drawing is separate.

The new eight-byte progress.v2 record restores current glows and checkpoint on
reload, placing the player safely at that checkpoint rather than at an arbitrary
mid-jump coordinate. Existing valid progress.v1 records migrate as aggregate
best/completion records; those original bytes remain untouched. Rejected writes
retain good stored data, keep play available and show SAVE PENDING; resume retries.
A corrupt record is reported and can be replaced by later valid progress.

Atlas, surface, authored font, prepared text and reusable chirp/OGG sources load
once and survive ordinary restarts. Deinit releases layouts before the font and
explicitly unloads audio. Music retries when browser output becomes ready after
a trusted gesture; no reload/mute-toggle is required. Atlas hot reload remains
native-only; prepared font layouts borrow immutable metrics, so font edits now
require the normal rebuild. This supersedes the README's older font-reload recipe.

The authored image/font/OGG retain existing generators and OFL notice. New short
original effects are generated by `python3 script/generate_reference_game_sounds.py`
from the engine root, without external samples.

Current checks: 20 Debug/ReleaseFast tests, browser build, ordinary keyboard/controller
680-tick full routes including every glow, checkpoint death/respawn, explicit
restart, completion/replay, plus storage, jump-boundary and lifecycle regressions.
These are automated normalized input, not physical controller or external user
testing. Native, Chromium/Firefox/real Safari, archive and bounded performance evidence
is recorded in the dated review, including hardware and input limits.

Optional verification (from engine root):

```sh
(cd dogfood/lantern-leap && zig build export-browser-replay -- zig-out/evidence/browser-route-input)
node script/reference_game_browser_route.mjs --game lantern-leap --browsers chromium,firefox,safari
node script/reference_game_trusted_browser.mjs --browsers chromium,firefox,safari
python3 script/test_reference_games_external.py
```

Safari needs real Safari Remote Automation and an owned safaridriver service on
port 4444. The exporter uses canonical BrowserInput; the server uses shared
replay.mjs, preserving PNG/readback probes and RGBA channel tolerance 1.
Normal package/web steps install no replay driver or exporter. For a virtual
controller, use `zig build export-browser-replay -- zig-out/evidence/browser-controller-input controller`.
Native/profile builds and evidence are in the dated review. A transient initial
read failure delays writes until existing progress can be read and merged;
explicit R still replaces the current run after recovery. Good stored bytes
remain intact while reads are unavailable, even if the backend accepts writes.
