# Neon Siege — current guide

A compact endless arena survival game. Clear successive waves, recover energy
and improve the best score. Current controls/save rules supersede the historical
README. Bounded acceptance criteria: [POLISH_PLAN.md](POLISH_PLAN.md). Cross-host
verification is recorded in [REVIEW-2026-11-12.md](REVIEW-2026-11-12.md).

```sh
cd dogfood/neon-siege
zig build run -Doptimize=ReleaseFast
zig build test
zig build test -Doptimize=ReleaseFast
zig build package web
python3 -m http.server --bind 127.0.0.1 --directory zig-out/web 8000
```

Open http://127.0.0.1:8000/?renderer=webgl2 and focus the game. `zig build dev-web`
uses the existing rebuild/reload workflow. Native output uses a 960×600 window;
the logical Canvas is 320×200. Package the complete web directory, including
unpolished-peas.wasm and licenses/Basic-OFL.txt.

- Enter / Start begins, pauses/resumes play, or immediately restarts after death.
- Arrows/WASD, D-pad or left stick move. Movement sets aim unless explicit aim is
  supplied by IJKL or the right stick; that supports shooting while repositioning.
- Hold Space, South or right shoulder to fire at a fixed cadence.
- Hold X / East to sprint. This is a held speed boost, not a discrete dash, and
  provides no invulnerability or stamina mechanic.
- Escape / Start pauses. R / left shoulder explicitly starts another fresh run.
- M / Back toggles effects/music. Tab retains normal browser focus navigation.

The entire bounded arena stays visible. Spawn outlines warn for 45 fixed ticks
and cannot hurt early; enemies appear safely away from the player. A brief
between-wave interval allows recovery. Headcount increases to eight, health to
four and speed increases for twelve waves before plateauing. The game stays
endless. Hits provide 30 fixed ticks of recovery, shown by a static outline and
notice; sprinting does not grant that protection. Energy gives points and repairs
one hull point when needed. Shot, hit, pickup, wave and death cues differ.

Preferences and best score retain the original settings.v1 six-byte format.
Current score, hull, enemies and wave reset on a new run or launch. Missing saves
use defaults; corrupt records are reported. Failed writes retain good stored
bytes, keep play available and show SAVE PENDING. Resume/restart retries while
retaining the in-memory best. Exact process/browser reload evidence follows in
the dated review rather than being inferred from in-memory tests.

Assets, prepared authored text, the world surface and audio sources load once
and survive ordinary restarts. Cleanup explicitly releases sources and layouts
before the borrowed font. Browser music retries once output is ready following
a trusted gesture, without an extra mute toggle or reload. Atlas hot reload stays
native-only; immutable prepared font metrics now require a rebuild after font
edits, superseding the README's older font-reload recipe.

The existing sprite/font/OGG sources and OFL notice remain. New short original
chirps are generated by `python3 script/generate_reference_game_sounds.py` from
the engine root, using no sampled third-party audio.

Current evidence: 21/21 Debug and ReleaseFast tests, full ordinary keyboard/
virtual-controller routes reaching wave four, damage/healing, sprint, pause,
death/restart and stored best/preference. Chromium/Firefox/real Safari pass CPU
renderer references and explicit shutdown; native process reload and archive
consumer checks pass. The dated review records exact reports and bounded
profiling. Game trace/pixel expectations changed after inspecting the full-arena
view, prepared font/HUD and wave transitions; engine and asset goldens remain
unchanged. Arranged combat captures are labeled and supplement the full routes.

Safari requires the existing real Safari Remote Automation prerequisite and an
owned safaridriver service on port 4444. The route exporter uses the canonical
BrowserInput codec; the test host uses shared replay.mjs. No replay tooling is
installed by normal package/web steps. Virtual-controller export is
`zig build export-browser-replay -- zig-out/evidence/browser-controller-input controller`.
The dated review contains exact native verification/profile builds and results.
Transient initial read failures delay writes until a successful read can retain
the existing best and preference; a deliberate new audio choice takes precedence.
