# Ashen Causeway development build

This is an unfinished action RPG prototype. The complete scope and acceptance
gates remain in [DESIGN.md](DESIGN.md). First-run pacing assessment and final
encounter/presentation review remain open.

From this directory, using Zig 0.15.2:

```
zig build test
zig build run
zig build web
python3 -m http.server --bind 127.0.0.1 --directory zig-out/web 8000
```

Open http://127.0.0.1:8000/ for the browser build. Native uses SDL3; the public
package dependency currently points to the engine checkout two directories up.
The archive-consumer command below verifies the public dependency boundary.

Arrows or left stick choose menu options; Enter, E or South accepts. Continue
restores a saved journey; New Game explicitly replaces progression while retaining
settings. Escape/Start opens pause and backs out of settings. WASD/arrows move and set facing. Moving the mouse sets aim;
J/left click attacks, K/right click performs a heavy attack, Space dodges,
H heals, Q switches sabre/spear, E interacts, Escape pauses. Select Resume or
press Escape/Start to resume. After death, Enter/E respawns. Controller bindings: left stick moves,
right stick aims, shoulders attack, South dodges, North heals, West interacts,
Back switches weapons and Start pauses/resumes. Physical controller validation
has not been performed.

Each area is 960×540 world pixels, viewed through a 480×270 camera. The lantern
at (70,270) restores health/stamina/flasks, resets enemies and sets the checkpoint.
The bell at (870,450) opens that area's east passage; E near x>900 travels east.
E near x<50 travels back west. Ringing the Cloister bell unlocks a lift at
(110,450) in both first areas. A Cloister reliquary at (480,100) grants 75 embers, a
fourth flask and the reed charm.
Enemies have distinct geometric silhouettes, anticipation poses and attack-region
outlines. The Pike thrust and Hound charge have narrow corridors; Drifters and
the Warden cleave a fan. The Censer launches a moving shot along its committed
aim. Warden phase two alternates faster melee with an expanding bell shock.
Dodge through the ring or retreat beyond its reach; the inner space is safe.
[DESIGN.md](DESIGN.md) records exact timings and damage. Once the Warden is defeated, ring the third bell and interact
with it again to rekindle the beacon, then view victory and credits. This build does not meet completion gates.

Death drops carried embers, replacing any earlier drop even if carrying zero.
Walk over the drop to recover it once. Respawn resets enemies and combat resources
but preserves bells, lift, reliquary and boss defeat.

At a lantern, pause and choose weapon or vitality upgrades. Each has three levels,
costing 50, 100 and 150 embers. Weapon levels add six damage each. Vitality adds
15 maximum HP per level; rest to fill the new capacity. Equip/remove the reed
charm at a lantern: it adds 25 maximum stamina and reduces walking speed from
102 to 90 world pixels/second. Normal regen and healing respect equipped capacity.

Saves use the portable SaveStore key `journey-v1`, explicit format `ASH1` version
1, forty bytes with a corruption checksum. They persist checkpoint, currency and
drop location/amount, weapon, upgrades, bells, shortcut, reliquary/charm, boss
victory, ending and settings. Autosaves occur when these values change. Pause
provides Save/Retry. Continue starts at the last lantern with restored resources
and reset normal enemies; transient position, HP, attacks, timers and enemy combat
state are excluded. Missing saves allow Begin. Invalid/unreadable saves show an
explanation and remain untouched until New Game is selected. A failed write keeps
the last good blob and a visible warning; retry after storage becomes available.

Settings persist and apply separate music/effects volumes, optional camera shake
and hurt flashes; intrusive effects default off. Original soft bell/drone music
and seven short cues are generated by `python3 tools/generate_audio.py`. Sources
and provenance are retained. Normalized PCM/muting/release and real browser audio
submission are tested; physical speaker quality has not been evaluated.
Browser reload, rejected-write preservation and retry have been exercised in
Chromium/Firefox; native SDL and all three browsers also reload the completed
journey in the route checks below.

See [PROGRESS.md](PROGRESS.md) for checks actually run and [FRICTION.md](FRICTION.md)
for framework observations. Test passage alone does not establish game polish,
play duration, enjoyment, renderer parity or hardware compatibility.

On a new journey, the bottom hint walks through movement, committed attacks,
stamina/dodging, vulnerable healing and lantern replenishment as those actions
are used. Continue skips that initial tutorial. Rejected/expired actions leave a
brief textual cue and sound; hit/hurt cues accompany the corresponding events.

Deterministic complete-route checks are part of `zig build test`. To retain
headless gameplay PNGs and public input replays, run:

```
ASHEN_ROUTE_EVIDENCE=zig-out/evidence/routes zig build test
```

They cover winning with keyboard/mouse and virtual controller input, both boss
phases, checkpoints, a menu upgrade, optional reward, lift traversal, save/continue,
fixed-input replay, plus a separate death/currency-recovery route. These are
headless automation. Separate real-host replay checks are documented below.
The automated routes are much faster than a first human run and do not verify
the 15–30 minute pacing target. At victory, Escape/Start retries a failed save;
the status text reports whether the ending has actually been saved.

The UI uses embedded Source Sans 3, with its notice packaged at
`assets/SourceSansOFL.txt`. Static labels are prepared once at initialization;
`python3 tools/prepare_labels.py` refreshes the finite label catalog after copy
edits. Numeric HUD values use allocation-free direct text drawing. Lanterns,
bells, the lift and reliquary have distinct shapes and interaction labels. An
edge marker points toward the next bell/passage, or the Warden in the Crown.

For real Safari smoke verification, serve the built web directory on port 8114,
start a free WebDriver service, then run from the engine root:

```
safaridriver -p 41245
node dogfood/ashen-causeway/tools/safari-smoke.mjs
```

Run the service in a separate terminal and stop it after the check. Safari remote
automation must be enabled. The script reuses the repository's real-Safari adapter,
requires strict renderer readback, checks settings/save/Continue after reload, and
restores any pre-existing journey in that test origin. It does not stand in for physical IME/controller testing. The separate route
check below covers a complete normalized-input Safari journey.


Full-host integration checks, from the engine root:

```
python3 script/test_ashen_causeway_external.py
python3 script/test_ashen_causeway_native.py
cd dogfood/ashen-causeway
ASHEN_ROUTE_EVIDENCE=zig-out/evidence/routes zig build test -j2
zig build export-browser-replay -Doptimize=ReleaseFast -j2 -- zig-out/evidence/routes/keyboard_mouse.upr zig-out/evidence/browser-route-input
cd ../..
node dogfood/ashen-causeway/tools/browser-route.mjs --browsers chromium,firefox
```

The external check creates a hashed source archive, fetches it into a fresh cache,
and builds/tests/packages/runs a copied game outside the checkout in a path with
spaces. It preserves authored sources and notices and retains its browser output
for the browser route check. Reports and command logs are in
`zig-out/diagnostics/ashen-external`. It uses a loopback archive server and does
not publish anything.

The native check opens a real SDL window, applies recorded normalized input once
per fixed update, completes the journey, verifies the saved bytes, closes, then
loads that journey in a second process. Its UUID save namespace is separate from
the game. Reports and CPU Canvas captures are in
`zig-out/diagnostics/ashen-native`; these are not native GPU readbacks.

The browser route check uses the archive-built bundle by default. A test-only
HTTP shim injects normalized snapshots and advances the real Wasm/browser host
at synthetic 60 Hz. It checks the entire route, ending storage and actual page
reload, plus six full RGBA readbacks against CPU references at the existing
one-channel-unit tolerance. Reports/captures are in
`zig-out/diagnostics/ashen-browser-route`. To include Safari, start its WebDriver
service as above and pass `--browsers chromium,firefox,safari`; set
`UP_SAFARI_WEBDRIVER_URL` if using another port. Stop your service afterwards.

These checks are automated input replay, not physical input, play-duration or
performance measurements. The trusted-input smoke checks cover real browser
keyboard/pointer integration separately. Verification hosts/exporters are optional
build steps and add no replay bridge to the shipped game.

[PROFILE.md](PROFILE.md) records complete-route CPU/allocation observations and
short real SDL ordinary/boss measurements, with exact reproduction commands and
boundaries. The optional `build-profiling`/`profile-route` targets do not change
normal run/package output.

For a slowed combat capture review, add `--motion` to `tools/browser-route.mjs`
and select one browser. For example, from the engine root:

```
node dogfood/ashen-causeway/tools/browser-route.mjs --browsers chromium --motion --output zig-out/diagnostics/ashen-motion-review
```

The current reference route's windup/approach and phase-two shock excerpts advance
one fixed tick per 166.7 ms wall delay (10% speed, slower during capture), saving
a full readback every ten ticks. Tick ranges are deliberately tied to this route;
update them when the reference input changes. These are visual inspection aids,
not timing measurements or physical gameplay recordings.
